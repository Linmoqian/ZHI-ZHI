# 回合树重构

> 用一棵随消息生长的「回合树」取代当前的「节点 + 消息链」两层结构。
> 地图就是树本身，每发一条消息树就长大一分。

## 动机

当前模型有两层独立结构：

- **节点树**（`LearningNode`）：通过 `parentId` 形成多叉树，是地图的骨架。
- **消息链**（`StoredMessage`）：每个节点内是一条线性链，通过 `parentId` 串联。

问题在于节点是冗余的中间层——它把「话题分组」硬塞在消息之上，导致地图和对话是两套结构，且消息链本身不能分叉。

统一为一层后：**消息即节点，树随消息生长**，地图直接渲染这棵树。

## 设计决策

| 决策 | 选择 | 说明 |
| --- | --- | --- |
| 树节点的粒度 | **回合（a）** | 一个树节点 = 一次用户输入 + 一次模型输出 |
| 子指针的存储 | **混合（C）** | `parentId` 为不可变核心，`childIds` 为可重建的派生索引 |
| 上下文语义 | **分叉即隔离** | 从叶到根的唯一路径即为纯净上下文，无需 `inherit/isolated` 开关 |
| 推进方式 | **先重构数据，一次性推进，过程小步提交** | |

其余三项：

- **节点状态**：回合无状态，丢弃整个 `NodeStatus` 状态机（current/exploring/mastered/merged/locked 全部移除）。
- **颜色与坐标**：按树深度 / 分支自动派生，不再手动存储 `tone` / `position`。
- **主题与标题**：会话主题 = 根回合的 user 输入；回合无独立 title，显示时用 user 输入的概括（复用概括生成能力）。

## 目标数据结构

```typescript
// 一个树节点 = 一个回合（user 输入 + assistant 输出）
type TurnNode = {
  id: string
  parentId: string | null        // 父回合，null = 根回合
  userContentHash: string        // 用户输入（内容寻址去重）
  assistantContentHash: string   // 模型输出（内容寻址去重）
  createdAt: string
}

// 会话 = 一棵回合树 + 内容仓库
type SessionRecord = {
  id: string
  topic: string                  // = 根回合的 user 输入
  createdAt: string
  turns: Map<string, TurnNode>
}
```

派生索引（不持久化，从 `turns` 重建）：

```typescript
childIndex: Map<string, string[]>   // parentId → [子回合 id…]
rootTurnId: string                   // parentId === null 的回合
```

回合内容仍走内容寻址（`ContentStore` + contentHash + 引用计数去重），保持与现有机制一致。

## 树形示意

```
回合1 (root): user「什么是注意力」+ assistant「它是…」
   │
   ├─ 回合2A (主线继续): user「举个例子」+ assistant「比如…」
   │    │
   │    └─ 回合3: user「懂了，再深入」+ assistant「…」
   │         (回合3 的上下文 = 回合1 → 2A → 3，纯净)
   │
   └─ 回合2B (分叉): user「换个角度」+ assistant「…」
        (回合2B 的上下文 = 回合1 → 2B，看不到 2A 和 3)
```

核心性质：**上下文 = 从叶到根的唯一路径**。因为每个回合只有一个 `parentId`，回溯路径唯一，分叉天然隔离。

## 核心算法

| 算法 | 操作 | 复杂度 |
| --- | --- | --- |
| 生长（追加） | 在某叶回合后追加新回合 | O(1) 写 + O(1) 更新索引 |
| 分叉 | 在某回合后长出新子回合（成为兄弟） | O(1) |
| 上下文回溯 | 从叶沿 `parentId` 到根，收集路径 | O(深度) |
| 找子回合 | 读 `childIndex` | O(1) |
| 找叶回合 | 找无子的回合（活跃分支末端） | O(回合数) |
| 克隆 | 在某回合再长一个子回合（= 分叉） | O(1) |
| 地图渲染 | DFS / BFS 遍历整棵树 | O(回合数) |

### 上下文回溯（纯净性的保证）

```typescript
function compileContext(turnId, turns): TurnNode[] {
  const path = []
  let cursor = turns.get(turnId)
  while (cursor) {
    path.push(cursor)
    cursor = cursor.parentId ? turns.get(cursor.parentId) : null
  }
  return path.reverse()  // 根 → 叶的时间顺序
}
```

每个回合只有一个 `parentId`，回溯路径唯一，自动实现「分叉后互不可见」——不再需要 `isolated / inherit` 开关。

## 持久化事件

回合模型下核心 mutation 只有两类：

- `turn_appended`：生长 / 分叉，新增一个回合（自包含：携带回合结构与内容）。
- `turn_updated`：编辑回合内容（user 或 assistant 文本变更）。

相比当前 5 种事件类型（`message_appended` / `branch_created` / `branch_merged` / `node_updated` / `node_unlocked`），回合模型的事件更简洁。

事件设计原则不变：自包含、纯数据应用、重放不触发模型调用或副作用。

## 功能映射（旧 → 新）

| 当前功能 | 回合树模型下的形态 |
| --- | --- |
| 创建会话 | 创建根回合（首轮 user + assistant） |
| 发送消息 | 在当前叶回合后追加子回合（生长） |
| 创建分支 / 克隆 | 在某回合后长出新子回合（分叉，成为兄弟） |
| 合并分支 | 将支线结论作为新回合接回主线某点（待定具体语义） |
| 上下文编译 | 从叶沿 `parentId` 回溯到根 |
| 地图渲染 | 直接 DFS / BFS 遍历回合树 |
| 节点概括 | 回合显示标签 = user 输入的概括（复用概括能力） |
| `NodeStatus` 状态机 | 移除 |
| `contextMode`（inherit / isolated）| 移除（分叉即隔离） |
| `tone` / `position` | 移除，由树布局与层级自动派生 |

## 取舍记录

- **为什么选回合粒度而非单条消息粒度**：回合粒度更贴近「一轮对话」的认知，分叉点在整轮之后，语义清晰。单条消息粒度虽更灵活（分叉可发生在 assistant 回复之后任意处），但增加结构复杂度，且与「一轮对话」的用户心智不符。
- **为什么用混合索引而非纯父指针或纯子指针**：纯父指针保持不可变但反向查询慢（找子回合要全表扫描）；纯子指针查询快但写入破坏不可变。混合方案以 `parentId` 为不可变核心，`childIds` 为可重建派生索引，兼顾两者。
- **为什么移除状态机**：回合树的纯净性来自结构本身（分叉即隔离），状态机会引入与树结构正交的额外语义，增加复杂度。当前阶段优先保持结构纯粹，状态需求后续按需再加。
